# CLAUDE.md — как работать с этим проектом

PWA «Лекарства-помощник»: напоминает пациенту о приёме лекарств, ухаживающий отмечает
выдачу, родственник видит статус и получает уведомления в Telegram. От приложения зависит
приём лекарств пожилым человеком — не ломай его и не гадай, проверяй по месту.

Архитектуру, состав файлов, настройку синхронизации и ИИ-скана см. в [README.md](README.md).
Здесь — только то, без чего сразу наделаешь ошибок.

## Репозитории

| Что | Репозиторий | Видимость |
|---|---|---|
| Клиент (этот каталог), remote `origin` | `eliduc/lekarstva` → GitHub Pages | **публичный** |
| Stage-клиент, remote `stage` | `eliduc/lekarstva-stage` | **публичный** |
| «Сервер» = хранилище данных | `eliduc/lekarstva-data` | приватный |
| Данные stage | `eliduc/lekarstva-data-stage` | приватный |

Всё, что коммитится сюда, становится публичным. Секреты, Telegram chat id, клинические
подробности и имена — только в приватный data-репозиторий или в локальный `knowledge/`.

Среда определяется в рантайме по URL (`/lekarstva-stage/` или `?env=stage`); у всех
project-pages один origin, поэтому ключи localStorage в stage префиксуются `stage:`.
Telegram в stage жёстко выключен. Деплой stage: `git push stage main`.

## Три канала синхронизации (все — через GitHub Contents API, строго по очереди)

- `backup/data.json` — конфиг (лекарства, расписание, времена, хэш пароля). Монотонный
  `generation` + compare-and-swap по `sha`. Секреты в облако не уходят (`cleanState`).
- `status/live.json` — живой статус дня `{date, slots, box, ts}`, опрос ~20 с, слияние LWW.
  При **разных** датах слоты меньшей даты выбрасываются целиком — отсюда дефект №1.
- `log/<iso>.json` — вечный журнал событий, только дозапись, слияние union по `id`,
  никогда не перезаписывается. Это единственное надёжное доказательство выдачи.

Сообщения о пропуске (missed) и вечернюю сводку (summary) шлёт **только сервер** —
GitHub Actions в data-репозитории (`.github/workflows/notify.yml` + `.github/notify.mjs`,
cron `7,37 * * * *`, TZ Asia/Jerusalem). Само приложение шлёт в Telegram только мгновенное
«Выдано» при отметке (`notifyGiven`), а по кнопкам в настройках — сводку и тестовое сообщение.

## Команды

```sh
node --test tests/*.test.js tests/security/*.test.js   # 97 юнит-тестов
# форма `node --test tests/` НЕ работает: node ищет модуль, а не каталог
cd e2e && npx playwright test # e2e, webServer поднимает http.server на :8200
python -m http.server 8000    # локальный запуск клиента
PYTHONIOENCODING=utf-8 python tools/build_pdfs.py && cd e2e && node render_pdfs.js
```

`tests/load.js` прокидывает приватные функции `sync.js` (`_mergeByTs`, `_cleanState`,
`_stableBody`) — исходник на диске при этом не меняется.

## Главные грабли

1. **Сутки считаем по Иерусалиму, не по часам устройства.** `dateISO()` (js/app.js:206)
   использует `Intl.DateTimeFormat('en-CA', {timeZone:'Asia/Jerusalem'})`, день недели —
   `weekdayIL()` (js/app.js:208). Никогда не возвращай `new Date().getDate()`/`getDay()`:
   устройство в поясе восточнее Израиля в свою полночь запишет пустой статус следующего
   дня и сотрёт отметки текущего. Так уже терялись данные (два дня в июле 2026).
2. **У токена `gh` нет scope `workflow`** (есть `gist`, `read:org`, `repo`). Файлы в
   `.github/workflows/` нельзя менять ни через Contents API, ни через push — только
   владелец через веб-интерфейс GitHub или после `gh auth refresh -s workflow`.
3. **В data-репозиторий пиши через Contents API** (прочитать `sha` → PUT), не через клон:
   репозиторий постоянно пишется приложением и Actions, `git push` падает non-fast-forward.
4. **`PYTHONIOENCODING=utf-8` для любого python-скрипта с кириллицей** — консоль Windows
   в cp1252, скрипт умирает уже ПОСЛЕ записи части файлов и тихо не доделывает остальное.
5. **Отсутствие сообщения в Telegram ничего не доказывает.** Cron GitHub Actions
   опаздывает на часы. Достоверные источники — отметка в приложении и `log/`.
6. **Смена дозировки правится в трёх местах:** облачный `backup/data.json` (это то, что
   реально видят устройства), `js/data.js` defaultState, `tools/build_pdfs.py`.
7. **Расписание в облаке уже не совпадает с `js/data.js`** — в `meds` остались препараты,
   убранные из назначения. Дефолт нужен только новым устройствам.
8. **Селекторы e2e:** строку приёма бери через `doseRow(page, time)` / `doseRows(page)`
   из `e2e/tests/helpers.js`, не по `.trow` и не по индексу — `.trow` носит ещё и баннер
   «заполните коробку».

## Подробности — в локальной базе знаний `knowledge/`

Бандл в формате OKF (markdown + YAML frontmatter), навигация от `knowledge/index.md`.
Он в `.gitignore` — там можно писать клинические детали и имена, но не секреты.
Читай оттуда только нужную сущность, не весь бандл:

- `knowledge/systems/` — клиент, data-репозиторий, среды prod/stage
- `knowledge/channels/` — три канала синхронизации и серверные уведомления, подробно
- `knowledge/defects/` — разбор дефектов: дата с часов устройства, шторм записей
  `live.json`, задержки cron, плавающий e2e
- `knowledge/clinical/` — назначение врача и печатные документы для пациента
- `knowledge/runbooks/` — пошагово: смена дозировки, деплой, разбор сообщения о пропуске,
  пересборка печатных документов. Начинай отсюда, если задача типовая
- `knowledge/incidents/` — разбор ложных тревог «Приём ПРОПУЩЕН» с методом расследования
- `knowledge/constraints/`, `knowledge/testing/` — ограничения среды и наборы тестов

Текущая версия: `APP_VERSION` в js/app.js, кэш service worker — `CACHE` в sw.js;
при изменении статики поднимай версию кэша, иначе устройства останутся на старом коде.
